# 锂电极片涂布机供浆智能运维 Agent：设计草案

状态：供用户审阅；未实施。日期：2026-10-27。

## 1. 目标与边界

做一个可在个人电脑上运行、可复现、可检查的模拟设备运维项目，面向设备智能体开发工程师的简历和面试。演示从工况回放、异常检测、证据检索、诊断、人工确认模拟处置，到执行后复核和报告。重点是工具、状态、来源和评测的可信边界。

设备为假设的狭缝式极片涂布机供浆子系统：供浆泵 → 简化阻力段 → 涂布头，设压力、流量和泵速测点。局部堵塞影响涂布的业务动机参考公开文献；变量、因果方程、数值、故障阈值、修复效果和配方约束均为项目自行假设，不是宁德时代设备数据、设备操作规程或实际安全参数。本项目不接 PLC、OPC UA 或真实设备，无远程生产控制能力，也不声称实际工厂效果。

岗位设备范围说明：用户提供的岗位描述以及本次找到的[第三方职位转载](https://www.shushuqiuzhi.com/position/486466)均未指定涂布机，因此无法断言该岗位具体负责涂布机。宁德时代[2022 年 ESG 报告](https://www.catl.com/uploads/1/file/public/202303/20230317104831_5qetsv0yiw.pdf)披露了智慧涂布、涂布重量自动调节及设备预测性维护，支持涂布作为公司锂电制造场景的一种选择，但不能证明该岗位负责此场景，更不能证明本模拟子系统对应实际设备结构。

## 2. 方案选择

- A：自行开发涂布机供浆子系统模拟闭环。已由用户选择；设备语境与岗位贴合，成本是需要清晰标注简化与验证边界。
- B：涂布机传动辊轴承，通用轴承资料较多但数据迁移到实际涂布机的依据有限。
- C：扩展现成工业运维项目，平台启动可能快，但上游维护、许可、个人贡献边界较复杂。

借鉴而不复制上游实现：Industrial Maintenance Copilot（MIT 代码，第三方数据独立许可）参考工作流，Predictive Maintenance MCP（MIT 代码，样例数据另有许可）参考诊断工具和证据表达。独立自研部分在 README 列出，所有复用的代码与内容保留许可、引用与作者；无许可证的代码不复制。

## 3. 演示与验收

### 主演示

1. 打开本地网页，选预置供浆阻力渐增案例，点击开始回放。读取公开工况，故障注入机制与真实标签仅限演示控制器/评测模块，Agent、检测和预测工具无法访问。
2. 展示最近工况曲线、异常事件与检测时间。压力趋势上升、流量下滑为模拟器中的模式，非现场通则。
3. 触发诊断。Agent 用工具读取固定窗口统计、报警、数据质量和知识卡片，给出堵塞、测点偏差等候选；每项关联事实证据、资料出处、反证/缺失项。数据不足或两种原因不可区分时明确保留不确定性。
4. 展示风险模型的“未来 30 分钟内出现模拟故障事件”的分数、模型版本与训练域；此分数不表示寿命、现实故障概率或真实工厂风险。
5. 在候选阻力异常达到模拟处置前提时，展示模拟检查并申请人工确认；确认后执行模拟清理、回放稳定窗口，复核压力/流量/检测状态。人工拒绝、不满足前提或执行失败均保留报警并结束为未恢复。
6. 在恢复后的健康模拟工况下，另运行受约束参数建议的离线实验，给出候选、对照和约束检查；默认不自动应用。导出 JSON/Markdown 报告与可追溯事件记录。

### 通过条件

- 空环境按 README 配置后能启动并复现案例；固定种子的确定性数据与指标可以重新生成。记录运行系统、Python、依赖锁文件、Git 版本、配置、种子和模型提供方/版本。
- 一条主故障链能展示注入、检测、模型分数、带来源诊断、人工确认、模拟处置及复核；至少一条传感器偏差或数据不足链不会误称已确定真实故障。
- 不配置大模型密钥时提供确定性演示与回归测试模式，明确标记为规则模板，不冒充大模型推理；配置兼容模型时可以运行真正的 LLM 工具调用。记录调用、失败、预算和输出校验，外部模型输出允许非确定性。
- 诊断中无法引用不存在的证据 ID；非法、无确认、超时或重复动作不会改变模拟器；日志记录请求、决策、前后状态和结果。
- 项目对合成数据和实际工业适用性有显著说明；不得声称真实自修复或产线提效。

## 4. 模块和数据流

```text
场景配置/种子 → 仿真器 → 只读工况/报警 API → 清洗与质量校验 → 规则检测
                                            ├→ 特征 → 风险模型
                                            └→ LangGraph 诊断工作流
                                                  ├→ 工况统计工具
                                                  ├→ 知识检索工具
                                                  ├→ 诊断结构/引用校验
                                                  └→ 动作建议 → 权限/状态门禁 → 人工确认
                                                                                  ↓
                                              审计 ← 复核 ← 仅模拟动作执行 ← 确认令牌

健康状态快照 → 有约束的离线模拟试验 → 参数建议与对照报告（默认不应用）
```

- Python：仿真、回放、特征、评测；Pandas/NumPy 用于数据处理；Pydantic 管理输入/输出 schema；FastAPI 提供本地接口；SQLite 存状态、审计和报告。轻量页面建议 Streamlit，与 FastAPI 共存；若部署成本过高可由简单 HTML 或 CLI 替代，但须有可展示的曲线与确认交互。
- LangGraph 管理状态与条件路由。单个 LLM 节点按需调用限定的只读工具，结果必须符合 schema；异常处理、约束检查与执行器由确定性代码负责，不让模型拥有执行权限。受控预算：每轮工具调用和重试上限写入配置，超限进入人工复核/证据不足状态。
- 模拟器接口与真实设备接口分离；MVP 不提供真实适配器。所有动作在同一进程或本地服务中作用于模拟会话。
- 各服务以 `run_id`、`scenario_id`、时间戳、`config_hash` 关联；保留模型和知识库版本。大模型服务、Embedding 与接口凭据放本地环境变量，不写入日志或仓库。
- 每个回放会话维护单调推进的模拟时钟。工况、报警和风险工具均在服务端强制截断到当前模拟时钟；请求未来时间直接拒绝，预生成的未来数据和标签对诊断方不可见。训练特征计算同样只读取窗口截至时刻之前的数据。

## 5. 仿真数据、变量与标签

### 时间、变量和场景

默认每分钟一个点，每个案例 360 点；全部数值为无量纲模拟单位（a.u.），明确不是工业量程。每条轨迹设独立 `asset_id`、`run_id`、seed、工况参数、故障类型、事件时间。公开给 Agent：时间、泵速设定 `pump_cmd`、线速度 `web_speed`、压力传感器 `pressure_obs`、流量传感器 `flow_obs`、可选温度 `temp_obs`、报警及缺失/质量标记。质量代理值 `coating_proxy` 可由流量与线速度的简化比例加噪声得到，命名为“模拟涂布量代理”，不称真实厚度或真实检测结果。

私有真值只存评测侧：阻力状态 `z`、泵效率 `eta`、真实压力/流量、故障注入事件、传感器偏差和故障标签；不同存储和 API schema 防止 Agent 与模型读取真值字段。案例：正常；阻力缓慢增长；压力传感器偏高；供浆泵效率下降；缺失/噪声；保留一种训练未见混合故障作为鲁棒性案例。仅两个核心诊断故障（阻力上升、压力测点偏差）必须完成，其他案例用于反例与增强。

### 一种可实现的生成机制

令 `u` 为泵速、`z≥0` 为模拟阻力、`eta∈(0,1]` 为模拟泵效率；使用一阶平滑让响应存在滞后：

```text
q_target = q_base × u × eta / (1 + a × z)
p_target = p_base + b × u × eta × z / (1 + a × z)
q_t = q_(t-1) + alpha × (q_target - q_(t-1)) + process_noise
p_t = p_(t-1) + alpha × (p_target - p_(t-1)) + process_noise
pressure_obs = p_t + sensor_bias + measurement_noise
flow_obs = q_t + measurement_noise
coating_proxy = q_t / max(web_speed, epsilon) + proxy_noise
```

其中 `a,b,alpha`、噪声、变量范围均为示例模型参数，并在配置文件留版本、说明和取值；`z` 随时间单调或带扰动增长、`eta` 可下降、偏差只影响被设定的传感器。通过不同 `asset_id` 随机生成基准值和响应系数，并设噪声、缺失、渐变/突发与速度波动。压力/流量变化仅是此泵曲线假设下的演示，不推断其他设备泵型或反馈控制下的变化方向。

异常规则依据观测值和训练集设阈值；不能读取 `z`。故障事件标签由模拟器预先定义：某轨迹首次 `z` 达到配置的 `failure_z` 为阻力故障事件。未来风险目标：对于观测时刻 t，若 t 后 1–30 分钟首次到达该事件为 1，否则为 0；若未来观测不足 30 分钟且没有发生事件，则删去该窗口而非标为 0。事件后窗口不用于该目标；已检测异常但故障事件尚未发生的窗口允许预测。传感器偏差/泵效率故障单独标注类型，不自动归为阻力事件正样本；对它们的错误高分单独统计。

模拟清理动作仅降低 `z`，其有效概率/残余阻力由场景配置设定；支持成功、无效及延迟恢复。执行后从动作时点的仿真器状态继续生成后续轨迹，而非继续播放预先生成的历史未来；保留动作前轨迹、仿真状态、随机数状态或分支种子、动作与分支 ID，使执行和复核可重放。真实标签只用于实验评价，不出现在诊断或评测时的输入证据中。固定 seed 可重放，但高分只代表对模拟器生成规律的拟合，不证明物理一致或迁移能力。

## 6. 预测、检索与工具编排

### 预测维保

基线为训练集确定的规则阈值/趋势和逻辑回归，候选 XGBoost；统一使用 t 时点以前的 10/30 分钟窗口特征，例如最近值、均值、斜率、标准差、缺失率和泵速；不使用未来、故障标记、隐藏状态、run_id/seed 等泄漏字段。训练/验证/测试按资产轨迹分组，约 70/15/15；同一资产所有轨迹固定属于一个集合，先划分再计算阈值和归一化，阈值只在验证集选择。测试正常、不同强度、不同漂移，以及训练未见的参数区间和混合故障单独报告；保留测试集不参与调参。预测事件不叫 RUL。UCI AI4I 如用作独立补充，标记为合成机器故障分类，不能并入本场景模型数据或当作外部真实验证。

### 知识库和 RAG

初始手工整理约 10–20 张知识卡，覆盖设备流程、模拟器假设、常见候选原因、缺失信息、诊断限制、仿真动作和参数约束。每张卡含 `id`、标题、设备/子系统、适用条件、证据类别（公开资料/项目假设/模拟操作规则）、来源 URL、出处定位、编者、审阅时间、版本、限制和内容；只存必要的自行概括内容，尊重原文许可。公开文献不被当成具体模拟阈值来源。

首版使用 BM25 与结构化过滤（子系统、证据类型、版本），返回卡片 ID 和来源；如测试证明语义召回不足，再加 Embedding + RRF 并与 BM25 比较，不依赖向量数据库。Git 管理知识卡与索引构建配置，报告记录知识库版本/哈希。固定一批人工整理的查询、相关卡和不可回答问题，按 Recall@k、MRR、引用有效率、无证据拒答率及错误引用分析；问题与知识卡由同一作者写会有偏差，需留人工对抗样例并声明局限。

### 工具与状态

只读工具：`get_window(run_id, end_time, duration)`、`summarize_window`、`get_alerts`、`get_prediction`、`search_knowledge`。返回有来源和时间边界的结构化对象并做参数校验。诊断输出含 `observations[]`、`candidates[]`、各自的 `supporting_evidence_ids[]`、`missing_or_conflicting[]`、`recommended_next_step` 和 `uncertainty`；候选排序是诊断建议，不伪装为已校准概率。

状态包括 `OBSERVING → ALERTED → DIAGNOSED → AWAITING_CONFIRMATION → ACTION_EXECUTED → VERIFYING → RESOLVED / UNRESOLVED`；也可从未确认/失败终止为 UNRESOLVED。模型不能直接改状态或执行动作；系统检查会话、前置条件、白名单、参数、确认令牌、有效期、状态版本、幂等键和单次使用。拒绝、超时、冲突与异常均留审计记录。动作前后使用两个互不重叠窗口，预先配置稳定持续时间、容许缺失比例及阈值；若未恢复、无足够数据或另有报警则保持 UNRESOLVED。

## 7. 参数优化与模拟处置

优化仅作用于恢复后的健康状态副本；先保存当前运行快照。候选泵速按离散网格搜索，线速度固定；范围、单次步长与压力/流量界限全部作为标记为“仿真示例”的配置。目标为模拟涂布量代理偏离目标的绝对值加泵速变化惩罚，候选超过压力或流量界限即淘汰；没有可行候选就返回无建议。每个候选与当前参数从相同初始状态、相同随机扰动序列进行多次仿真，报告各次和均值/波动、约束违规、基线及实验配置；设独立种子的重复试验检验稳定性。不是闭环真实控制或对真实涂布质量的证明。

允许的模拟动作只有 `inspect`、`simulate_clean_blockage` 和恢复健康场景下 `apply_simulated_setpoint`；后两者必须人工确认，前者只读。清理须有工况与数据质量前提，建议或不建议均由确定性门禁校验；模拟动作和参数执行有可复现回滚或状态快照。用户拒绝时不得执行，恢复状态只由复核规则决定。任何高风险真实动作均不在系统能力范围。

## 8. 评测设计与复现

- 数据生成：记录代码版本、依赖、配置、种子；发布生成脚本和清单，不依赖未授权原始数据。按资产分组预先固定划分文件及 SHA；测试集不得用于拟合、调阈值或选择提示词。
- 感知：事件级检出率、正常轨迹每小时误报警数、故障事件前检出提前量；规定匹配窗口与重复报警合并规则，分别统计漏报和缺失数据案例，避免按时间点堆叠抬高指标。
- 预测：报告按轨迹分组的测试集 PR-AUC、精确率/召回率、Brier 分数或校准图，以及每轨迹触发的误报警和事件预警提前量；明确正样本比例、阈值、可信样本量和跨 seed 变化。对比规则、逻辑回归和 XGBoost；模型效果不及基线则如实说明。
- RAG：报告 Recall@k、MRR、证据 ID 与出处正确率、无相关资料案例的拒答率；展示至少一个同义表达、冲突证据和资料缺失的失败案例。真实工业专家标注缺失需注明。
- 工具与流程：对合法/无效参数、工具超时、模型输出不合格式、虚构引用、重复动作、未确认、拒绝、超时、版本冲突、处置无效及复核数据不足做可重复检查；汇报各案例的结果而非仅展示成功率。
- 诊断：固定案例标注可接受候选和必要证据，报告候选覆盖率、引用支持率、证据不足识别率，保存失败案例；不将合成标签称真实诊断准确率。
- 复现：README 提供安装与启动、生成数据、训练、评测、回放主案例及导出报告的实际命令；命令以实现后为准。模型报告列数据边界、划分、模型版本、特征、指标、负例与运行时间；录制完整成功和失败演示。

## 9. 范围、阶段与估时

时间以具备用户现有技术背景、单人工作、简洁本地页面为假设，属估算而非承诺。

| 优先级 | 内容 | 工作量 |
| --- | --- | --- |
| P0 | 场景与文献、仿真器/回放、规则检测、可复现数据与划分 | 12–18 小时 |
| P0 | 知识卡、BM25、工具、LangGraph、证据校验与离线模式 | 12–18 小时 |
| P0 | 本地页面、人工确认、白名单动作与复核、报告 | 12–18 小时 |
| P1（纳入首版） | 未来 30 分钟模拟故障风险、基线、XGBoost、评测 | 8–14 小时 |
| P1（纳入首版） | 受限网格实验、参数建议、约束/反例测试 | 5–8 小时 |
| P1（纳入首版） | 全流程评测、README、示例报告和演示录制 | 8–12 小时 |

合计约 **57–88 小时**；如依赖服务适配、缺陷修复或设计返工较多则增加。为应对时间不足，先交付 P0 的单案例闭环，再依次补预测和参数实验；未实现的内容不得在 README 和简历中写成已完成。后续增强包括 Embedding/RRF、更多设备故障、公开数据的独立 benchmark、专家评审、更多真实资料对齐；不以多 Agent 或接真实设备为默认增强目标。

## 10. 展示、面试和简历
