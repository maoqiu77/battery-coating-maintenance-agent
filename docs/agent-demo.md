# 模拟运维 Agent：闭环验证与三分钟演示

这是用于展示 Agent 工程设计的本地模拟项目。模拟器提供观测和受控动作，Agent 通过观测、检索、独立检查、规划、审批、执行及复核完成有界任务。它没有连接 PLC 或真实生产设备。

工作台入口是左侧“Agent 工作流”：选择工况、填写目标及规划模式后，点击顶部“新建闭环演示”即可新建会话并启动 Agent；已有会话也可点击“启动 Agent 闭环”。其他页面的“运行诊断演示”是原有规则诊断快捷入口。这里的每次“批准本次模拟动作”只对应当轮动作，后续不同动作仍需再次确认。

## 一次任务的实际边界

1. 启动任务后，按预算采集模拟观测、检测数据质量和异常、检索知识证据。
2. 计划器根据当前证据选择独立检查工具，提出下一步建议。压力参考、泵台架和采集完整率检查都是新增的模拟测量；不把场景标签或隐藏阻力直接交给模型。
3. 写动作必须通过确定性门禁，并暂停等待本次动作的独立审批。确认绑定会话版本，有效期120秒；过期、重复或状态变化的确认不会执行。
4. 批准后才执行模拟动作，并续跑30分钟，以末20分钟的新观测窗口验证效果。恢复则结束；未恢复则重新取证规划，同一失败动作不会被无限重复申请。
5. 观测正常时结束本次观察，不执行修复。这里的 `MONITORING` 是本轮有界观察完成，不代表后台永久持续采集。

本地站内通知用于显示审批、恢复和转人工待办；它们没有发送到企业微信、钉钉、邮件或其他外部渠道。

## 规则规划与真实模型规划

`rules` 是离线的确定性规划，`llm` 才调用配置的外部模型。决策中的 `source`、报告中的 `actual_planner_sources` 和 `model_calls` 保留实际来源，不能把规则执行结果描述成真实模型决策。LLM 配置齐全也不等于调用成功；服务不可用或证据校验失败时，LLM 任务显式转人工，来源记录为 `llm_unavailable`，不会静默替换为规则动作。

本文已完成的真实调用使用 `COATING_LLM_MODEL=gpt-6.1-terra`、`COATING_LLM_API=responses`。克隆项目后，需按[README配置说明](../README.md#启用真实-llm)自行设置所用模型服务；项目根目录 `.env` 存放对应服务的私密凭据及可选兼容地址，API和LLM评测脚本启动时加载，已有进程环境优先。更换模型或接口后，应重新验证该配置，不能沿用其他模型的验收结论。

模型只能访问只读统计、知识检索和独立模拟检查，最后提交结构化决策；提交 `request_approval` 只是申请审批，并不赋予模型动作执行权限。模型输出还需通过实际取证引用、动作适用性及预算校验。目标为“只诊断”或“不执行”时，不应申请或执行写动作。

## 六种工况的预期终点

| 模拟工况 | 证据与动作 | 正确终点 |
| --- | --- | --- |
| 正常运行 | 观测未见阈值异常，无动作 | `MONITORING`，本次观察结束 |
| 供浆阻力上升 | 高压低流、独立压力参考；审批清理 | `RESOLVED`，新窗口复核恢复 |
| 压力传感器偏差 | 独立压力读数偏差；审批校准 | `RESOLVED` |
| 泵效率下降 | 低流量、虚拟空载台架效率下降；审批维护 | `RESOLVED` |
| 数据缺失 | 采集完整率不足；审批恢复采集 | `RESOLVED`，只恢复后续观测，历史缺口保留 |
| 混合异常 | 清理后仍有压力偏差，重新检查、再次审批校准 | `RESOLVED`，默认规则路径有两次独立审批 |

所有“恢复”都限定为模拟阈值和数据质量条件。混合异常的首次清理应仅改善流量与部分压力，不能直接宣布全部恢复。

## 可复现评测

在项目根目录运行：

```bash
uv run python scripts/evaluate_agent.py
uv run python scripts/evaluate_agent.py --include-negative-cases
```

默认固定种子42、离线规则规划、观察180分钟，每例最多四次动作，输出 `artifacts/agent-evaluation.json`。脚本使用隔离内存数据库，不修改工作台的 `audit.sqlite3`。它会自动批准模拟动作以驱动测试，输出明确标记 `approval_mode: "test_harness"`；这是测试夹具，不是实际用户审批，也不是产品绕过审批的功能。

额外两个负例验证：一次模拟动作失败后复核不通过，重新规划后转人工且不重复同一动作；“只诊断”目标不申请或执行动作。每例输出实际规划来源、模型/工具调用数、动作序列、最终状态、独立检查证据、前后与无动作对照统计及站内通知。

2026-10-29 已实际执行上述八例的规则模式评测：8例全部满足预期，真实模型调用数为0，工具调用总数为110。六种工况中正常运行以 `MONITORING` 结束且无动作，五种异常以 `RESOLVED` 结束；失败清理复核后以 `ESCALATED` 转人工，未重复申请同一动作。“只诊断”案例也以 `ESCALATED` 形成供人员查看的待办，但没有申请或执行动作。这里的8/8是这些自编固定案例的流程验收，不是故障诊断准确率。

例如，传感器偏差案例中，新验证窗口的压力均值为1.0086，无校准对照为1.4086；泵效率下降案例中，新窗口的流量均值为0.9687，无维护对照为0.7063。这些数值为种子42的无量纲模拟观测，不代表现场设备参数或工业收益。

有意评测真实模型时，可显式运行单例，确认当前服务配置与调用成本：

```bash
uv run python scripts/evaluate_agent.py --mode llm --scenario sensor_bias --output artifacts/agent-evaluation-llm-sensor.json
```

省略 `--scenario` 会运行六例；加 `--include-negative-cases` 会再运行两例。LLM 模式不是离线测试，规划每轮最多4次模型调用、12次工具调用；任务最多4轮。运行前应确认对应服务与预算，不能把未实际运行的模型案例写成已验证。

### 首轮真实 LLM 记录：2026-10-29

首轮八例真实调用使用 `gpt-6.1-terra` Responses，结果文件为 `artifacts/agent-llm-evaluation.json`。该首轮为5/8满足完整预期，记录23次模型请求尝试和127次工具调用；它与规则模式8/8是两份不同结果。审批仍由隔离测试夹具提供。

| 首轮案例 | 实际结果 | 验收结论 |
| --- | --- | --- |
| 正常运行 | 模型选择继续观察，无动作，`MONITORING` | 通过 |
| 供浆阻力上升 | 模型取证并申请清理，批准后恢复 | 通过 |
| 压力传感器偏差 | 模型取证并申请校准，批准后恢复 | 通过 |
| 泵效率下降 | 模型检查泵效率并申请维护，批准后恢复 | 通过 |
| 数据缺失 | 模型确认采集问题并申请恢复，批准后恢复 | 通过 |
| 混合异常 | 首轮清理完成，第二轮发生 `PlanningError`，显式转人工 | 未通过完整闭环验收 |
| 失败动作 | 首轮失败清理后，第二轮模型调用遇到限流 | 未完成模型再规划验收 |
| 只诊断 | 模型请求遇到限流，没有执行动作 | 未完成目标理解验收 |

后面三例虽然安全停止且没有未批准动作，仍不能算首轮完整模型能力验收通过。最新完整验收单独记录在上一节，不覆盖或删除这次失败结果。

新评测输出使用 `schema_version=2`：`model_attempts`/兼容字段 `model_calls` 计请求尝试，`model_completed_calls` 仅计成功返回到计划器的响应；未返回的尝试不等于已计费请求，返回响应也不等于形成有效决策。旧首轮报告没有单独记录完成返回次数，不能用23次尝试倒推该数。`planning_warnings` 优先读取固定错误码，按限流、超时、连接或规划校验等归类；正常的只诊断通知、模型有意转人工不算规划错误。它只保留本地生成的说明，不保存服务商错误正文、密钥或原始模型输出。

## 如何解释处置效果

每次动作前复制同一模拟状态。一份执行动作，一份不执行；两份使用相同过程随机扰动，各自续跑30分钟，比较末20分钟窗口。处置前基线则来自当时最近30分钟。图表和报告应保留窗口差异，不把不同窗口的均值包装成严格的真实因果估计。

报告 `effects` 中的 `before`、`after`、`control` 是实际模拟观测统计，包含压力、流量、完整率和告警状态。恢复采集新增的涂布量代理噪声使用独立确定性随机流，不改变共同过程扰动；未处置场景的原有训练轨迹保持不变。这里能证明的是当前模拟设定下动作对观测的作用，不能推导产线停机率、良率或维护成本提升百分比。

每例顶层 `before/after/control` 对应最后一次动作，并用 `comparison_scope: "last_action_only"` 标识；初始观测单独保存在 `initial_observation`。因此混合案例的最后一次对照是“已经清理但未校准”，不是从头完全不处置；两次动作各自的完整对照保存在 `effects` 中。正常和只诊断案例没有动作，对照字段为 `null`。

## 三分钟演示顺序

**0:00–0:30：说明边界。** “这是我实现的模拟设备运维 Agent，展示可追溯取证、规划、审批和执行后验证；不是工厂实机数据。”指出当前选择的是规则还是 LLM 模式。尚未实测的外部模型不要现场宣称已验证。

**0:30–1:10：先展示一个快速案例。** 选择压力传感器偏差并启动 Agent。展示压力偏高而流量正常、独立压力参考与偏差证据，再指出计划器提出校准而不是清理。审批前按钮停在等待状态，模型没有自行修改模拟器。

**1:10–1:50：展示批准与新窗口验证。** 批准本次校准，查看30分钟续跑后的独立验证、无动作对照及站内恢复通知。引用页面上的实际数值，不背诵固定提升率。

**1:50–2:40：展示混合工况再规划。** 选择混合异常并启动任务，第一次批准清理后，查看仍然偏高的压力和未恢复状态；Agent 重新调用压力检查，再申请第二次校准，第二次批准后才完成恢复。说明两次审批对应两次不同动作。

**2:40–3:00：展示可追溯结果。** 打开报告，指出每轮决策来源、工具证据、动作、效果和审计轨迹。补充失败动作会停止重复尝试，“只诊断”目标不申请写动作，通知目前仅在工作台内显示。

若真实模型响应较慢，先演示一个实际模型案例，再用已保存的真实运行报告解释混合再规划；离线规则演示要明确标注为规则。不要用预录或规则输出冒充当场模型调用。
